# Review experience

Current design authority for visual tokens is `DESIGN.md`: blue-black canvas, restrained blue focus, red risk, system CJK fonts, large preview, inspector, six-action belt and neighbor filmstrip. This specification adds behavioral qualification, not a UI redesign.

Borrow Picasa's named albums and light single-machine flow, digiKam's explicit confirmation states and tagging discipline, Immich's timeline/search and merge/split/hide discoverability, PhotoPrism's quiet presentation. Do not import their training or adaptive-threshold mechanisms invisibly (INV-1, FR-IDENTITY-001).

### FR-UX-001 — Evidence before action
When displaying a recommendation, the review studio shall separate model proposal from manual decision and expose requested/completed signals, uncertainty, profile identity and degradation reasons before confirmation.

Scope: S: review / E: offline browser / T0–T4. Status: proposed (existing studio implements a subset).
- Show quality means and HPS mu/sigma availability, disagreement, gaming audit state, family membership/champion ambiguity and routing reasons. Empty gaming delta means unaudited, never safe. Numeric intervals are not calibrated probabilities unless evidenced. All-abstain runs explain missing evidence and offer manual inspection, not lower thresholds automatically.
- Six actions remain select, approve queue, archive candidate, confirm safety route, question identity, skip; `1–6`, arrows/J/K, U, Space, F, ? remain discoverable. Archive is not delete. Manual journal exports JSON/CSV; localStorage is not backup. Exports do not bypass plan/token/digest confirmation.
- AC-FR-UX-001-01: walk SYN-STUDIO-v1 with missing HPS, ambiguous family, stale decision and all-abstain variants; every state visibly distinguished, model values unchanged after manual actions, zero direct moves; evidence `evidence/AC-FR-UX-001-01.json`.

### NFR-UX-001 — Offline accessible bounded review
When opening or navigating a review artifact, the studio shall remain network-independent, keyboard operable and bounded by declared browser memory and rendering budgets, or show an explicit blocking compatibility message.

Scope: S: review / E: declared Chrome/Edge versions / T0–T4. Status: proposed.
- Existing columnar gzip/base64 payload uses native DecompressionStream; unsupported browsers show a Chinese compatibility explanation. Synthetic fixture only for distributed screenshots. NSFW blur at ≥0.65 or route_nsfw is paired with text and explicit reveal, not safety assurance.
- CJK-safe labels, visible focus, focus restoration, reduced motion and no page-level horizontal overflow; WCAG 2.2 AA target, text contrast ≥4.5:1. Table overflow stays in its labelled region. Preview→thumbnail→placeholder fallback; virtual rows and bounded neighbor prefetch (existing six neighbors/four concurrent requests) do not establish a browser ceiling by themselves.
- AC-NFR-UX-001-01: keyboard, network-capture, accessibility and screenshot checks on SYN-STUDIO-v1 at 520/900/1440 widths and declared browser versions; zero network requests, clipped CJK controls or unreachable actions, ≥4.5:1 body contrast; memory/interaction ceilings TBD before browser qualification; evidence `evidence/AC-NFR-UX-001-01.json`.
